SSH Access Help

SSH Logs

The SSH Logs page allows you to monitor all connection attempts to your device's secure shell. It parses the system logs to show you:

  • Timestamp: When the attempt occurred.
  • Status: Whether the login was a SUCCESS, FAILED, or INVALID user attempt.
  • User: The username used for the attempt.
  • IP Address: The source IP of the connection.

Use the Refresh button to see the latest activity. Frequent failed attempts from unknown IPs may indicate a brute-force attack.

Critical Security Guidance: Known Threats

If you see an IP Address in the logs that does not belong to you, treat it as a targeted attack. Piso Wifi systems are frequent targets for community-driven exploits:

  • Exploit Distribution: Platforms like GitHub and PHCorner.org are known sources for "bypass" tools and automated scripts specifically designed to target vending systems.
  • Logic Modification: A successful SSH breach allows an attacker to modify the system's internal PHP logic. They can change rates, grant themselves unlimited "FreeNet" access, or redirect payments to their own accounts.
  • Defacement: Hackers may replace your portal or dashboard files with their own messages (Defacement), damaging your business reputation.
  • Brute-Force & Credential Theft: Automated bots use lists of common "Piso Wifi" default passwords to gain entry. If you see successful logins from unknown IPs, your system is already compromised.

The strict security architecture of this system is directly informed by the developer's background in investigating vulnerabilities and creating exploits for targeted brands. By utilizing this practical experience in how systems are compromised, the developer has implemented defense layers designed to stop even the most persistent "bypass" tools and logic modification attempts found in the wild.

Recommendation: Do not rely on a strong password alone. Enable SSH Restriction immediately to whitelist only your device MAC. This effectively "hides" the system from community exploits and automated scanners.

SSH Restriction

This feature acts as a firewall for your SSH port (22). You can manage who is allowed to connect remotely.

  • Open Access: Anyone on the network can attempt to log in via SSH.
  • Restricted Mode: Only devices with MAC addresses listed in your Whitelist can connect. All other connection attempts are dropped at the kernel level.

Safety Tip: Always click "Add Current Device" before enabling Restricted Mode to ensure you don't lock yourself out. If you do get locked out, you must use the Orange Star ID recovery or delete the config file via physical access.
