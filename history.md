## MODEL ✨

I've identified the cause. The issue lies in the `api/client` script, which is executed by the DHCP server (`conf/dhcpd.conf`) every time a device connects or renews its IP.

**The Flaw:**
The `api/client` script **only checks the Data Limit** and completely ignores the **Time Limit**.
```php
// api/client
list($mb_limit, $mb_used) = $db->get_data_usage(); // Ignores time_limit
if( $mb_limit > $mb_used ) { // Only checks data
    $ipt = new Iptables($ip);
    $ipt->add_client();
}
```
If a customer has a **Time-Based Voucher** (e.g., 1 Hour) that has a high or placeholder Data Limit (e.g., 1000MB or "Unlimited"), and their time expires:
1.  The Watchdog (`api/clients`) kicks them off because it checks Time.
2.  Their device reconnects to WiFi (DHCP Request).
3.  `api/client` runs, sees `Data Limit > Used` (ignoring that Time is expired), and **grants access again**.
4.  This creates a loop of "Kick -> Auto-Reconnect -> Grant Access", giving them internet access despite being expired.

I recommend patching `api/client` to respect time limits, and also updating `api/connect.php` which shares a similar logic flaw (allowing access if *either* Data OR Time is valid, rather than requiring *both* to be non-expired).
